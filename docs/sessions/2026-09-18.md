# 2026-09-18 工作总结

## 用户需求

实现洛克王国世界（roco）伤害计算器的第一步：从 wiki.biligame.com/nrc 爬取所有精灵信息，以 CSV 保存本地。每个精灵需包含：精灵编号、中文名称、六项种族值（生命/物攻/魔攻/物防/魔防/速度，均为整数）、进化链关系。

## 讨论过程中的关键结论

1. **数据源结构**：biligame 是 MediaWiki 架构，精灵数据不在 HTML 里，而是存在 Lua 数据模块中（`Module:Pets/data/Catalog` + `Module:Pets/data/Evolutions`）。直接通过 `api.php?action=parse&prop=wikitext` 拉取模块源码，解析 Lua 表，比解析 HTML 可靠得多。

2. **站点防护**：站点启用了腾讯 EdgeOne 防护，缺少 `User-Agent`/`Referer` 请求头会被拦截（HTTP 567）。补全请求头后可正常访问。

3. **种族值字段映射**：`stats` 表的键名 `hp/atk/def/spa/spd/spe` 分别对应 生命/物攻/物防/魔攻/魔防/速度，已通过渲染页的 `data-rune` 交叉验证（一窝蜂：生命87 物攻32 物防27 魔攻29 魔防27 速度26，总和 228）。

4. **形态变体共享编号**：621 只精灵中只有 466 个唯一编号，79 个编号被形态变体共享（如迪莫有 5 个形态共享编号 001，靠 `form` 字段区分）。

5. **领主化形态与前身共享编号**：进化链的 `lord_branches`（stage 4，首领化）与其前身（stage 3）共享同一个图鉴编号。因此用编号表示进化链会出现 `084→084` 的歧义，改用名称序列。

6. **多分支进化线**：一个 `evolution_id` 可对应多条分支线（数组含多个 `{chain, lord_branches}`），如迪莫有 4 个领主化分支。

## 最终采用的方案

- 技术栈：Python 标准库（`urllib` + 自写 Lua 表递归下降解析器），零第三方依赖。
- 数据范围：全部抓取 621 只精灵（含形态变体）。
- CSV 单表，每精灵一行，12 个字段（编号/名称/六项种族值/属性/阶段/形态/进化链）。
- 进化链列用名称序列（`→` 连接），因名称能唯一区分共享编号的领主化形态。
- 脚本支持 `--cache` 离线重跑，缓存模块源码到 `.cache/`。

## 需求变更（进化链语义细化）

用户补充说明：进化链关系不应出现 `迪莫→圣光迪莫→圣草迪莫→圣火迪莫→圣水迪莫` 这种把分支拼成一串的结果，迪莫只会**分别**进化成后四种形态。处理方式：

1. 对精灵 A，其进化链只写到**以 A 结尾**（分叉点之后的形态不展开）。
2. `form` 非空时，进化链中该形态以 `name(form)` 格式显示。

实现：把「合并同一 id 下所有分支成员」改为「保留每条分支线，对每条线的成员生成『从起点到自身为止』的前缀序列」。同精灵若出现在多条分支线（分叉点之前），前缀相同，取首次结果。

调整后示例：

- 迪莫 → `迪莫`
- 圣光迪莫 → `迪莫→圣光迪莫(首领形态)`
- 女王蜂 → `一窝蜂→黄蜂后→花魁蜂后→女王蜂(首领形态)`

全量校验：621 行进化链均以自身（含 form）结尾，无空链。

# 属性克制表（第二步）

## 用户需求

生成属性克制表。18 种属性，克制/抵抗关系为二元组 `(a, b)` 表示「用 a 系攻击 b 系」产生克制/抵抗；克制与抵抗不一定反对称。按指定爬取 ali213 攻略页获取关系表。

## 关键结论

1. **攻略页数据基本可靠**：ali213 攻略「三、克制关系一览」Step1~18 列出了 18 属性的克制/抵抗。解析出克制 49 组、抵抗 63 组。

2. **攻略有一处内部矛盾**：光系条目写「受到草/幽系的2倍伤害」（草→光克制），但草系条目「作为攻击方」只写克制水/地系，漏了光。用「作为攻击方」与「作为被攻击方」交叉验证发现唯一差异就是「草系→光系」。

3. **wiki 有更权威的数据源**：`Module:Pets/data/Types` 存了游戏实际的克制数据，含 18 单属性 + 102 双属性组合的 weak/resist。交叉对比确认：抵抗 63 组与攻略完全一致；克制 wiki 50 组、攻略 49 组，唯一差异「草系→光系」——攻略草系条目漏写。

4. **双克制倍率是 ×3 不是 ×4**：wiki 数据中双属性组合的倍率有 ×2/×3/×0.5/×0.25 四档，双克制（攻击方克制防御方两个属性）为 ×3，与攻略写的「双克制×4」不符，以 wiki 为准。

5. **用户决策**：属性克制表改用 wiki `Types` 模块为权威数据源。

## 最终方案

- 数据源：`Module:Pets/data/Types`（复用 `crawl_pets.py` 的 LuaParser + load_or_fetch）。
- 输出两个文件：
  - `data/type_relations.csv`：单属性克制/抵抗二元组（attack/defend/relation），克制 50 + 抵抗 63 = 113 行。
  - `data/type_multipliers.csv`：完整倍率表（defend/attack/multiplier），含双属性组合，1023 行。
