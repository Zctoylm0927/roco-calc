# 本地 CPU 识别与离线回合复核

当前有两个入口：`ocr_frame.py` 读取静态操作截图；`review_video.py` 从原分辨率视频的固定区域和已标注时间采样 OCR 证据，并导出人工复核过的回合记录。视频工具目前不自动寻找回合边界，也不会把固定样例当作新视频的识别结果。

## 已确认的方案

- 使用 PP-OCRv4 中文 mobile、ONNX Runtime CPU，关闭 GPU 和方向分类，模型与头像索引在进程中复用。
- 操作帧只从顶部头像判断身份；颜色、轮廓和 SIFT 筛选独立头像 Top 10，显示名只辅助核对，不改视觉排序。昵称可以与另一只精灵原名相同，不能独立确认身份。
- 分别裁剪生命、能量、技能名、画面威力及能耗，保留四个技能槽位；防御和状态技能没有威力。数据库基础威力不替代画面威力。
- 攻击帧只采样 HUD、行动提示和伤害，不匹配头像或场地精灵本体，不读取已经消失的四技能按钮。
- OCR 原文、置信度、采样时间和原始帧索引独立保存。归属不明或 UI 隐藏时使用 `null`，不能把缺失当成零。
- 低置信度名称可以用技能池辅助，但复写、借用、取念可能产生原生技能池外的技能。当前静态技能池校对尚未接入动态技能来源，不能据池外名称直接否定视频观察。

## 重取高清参考片证据

原片不在 Git 中。将用户提供的 `参考视频-高清.mp4` 放到仓库根目录，按 README 安装可选 OCR 环境和模型后运行：

```bash
python review_video.py extract "参考视频-高清.mp4" \
  --config configs/video_reference_hd.json \
  --output .cache/video_review/evidence --save-crops
```

配置对应 2560×1440 全屏录制、1920×1080 游戏内容区域 `[405,174,2325,1254]`。坐标是原视频像素；先裁剪再放大，不缩小完整屏幕。窗口移动、分辨率改变或时长不符时必须重新校准。尺寸、标题栏范围及超出视频的采样时刻会在加载 OCR 模型前检查。

先做一个采样点确认：

```bash
python review_video.py extract "参考视频-高清.mp4" \
  --kind hud --time 80 --output .cache/video_review/check --save-crops
```

该点我方生命应读到 `317/398`。`--kind actions`、`damage`、`energy_timing` 可分别重取行动提示、伤害和扣能时序；`--limit 3` 最多采样三个配置内时刻。模型只加载一次，视频按时间采样，仅保持当前完整帧和局部裁剪；输出为 `observations.json`，可选图像写入 `crops/`。检测框还原到原始屏幕坐标，纯单行识别没有检测框。

采样输出是原始证据。OCR 仍可能将斜线读为7、将星号读为其他字符，或漏读动画中颜色接近背景的数字。参考结果中的纠正来自邻帧和高清画面复核，不能以正则替换所有字母或套用数据库数字来冒充实际读数。

## 导出已确认的27回合

用户已确认的高清记录保存在 `data/battles/reference_hd.json`，不依赖本机缓存、截图或绝对路径。只导出记录时使用 Python 标准库，不需要 OCR 模型：

```bash
python review_video.py export --output .cache/video_review/reviewed
```

输出 `battle.json`、`summary.json`，以及 `turns/turn_001.json` 到 `turn_027.json`。每回合包含双方行动前后状态、按结算顺序排列的事件、能耗、显示伤害、强制切换和中文描述。读取新的视频需要新的区域配置、采样、身份与回合复核；此命令只导出指定的已复核 JSON。

这是识别侧的中文复核格式，尚未直接适配网页的 `/api/battle` 输入。计算后端的协议和示例见 `roco_battle.py`、`data/battle_example.json`；后续需要把身份、队伍槽位、效果和观察项映射后再用于对局推断。

记录将我方当前生命与上限、敌方生命百分比分开；双方能量独立记录。显示伤害与实际 HP 净变化不等同，例如显示伤害416时，我方剩余323生命实际降至0。能量变化同样需要分来源：炎枪/筛管奔流自身消耗3，报复应对再扣3，不能将总消耗6记成技能能耗。骨龙冬至提示无星号能耗，其7点消耗仍标注为依据10→3的观察所作的推定。

参考片有54个回合起止快照和14次最终技能伤害；270个适用数字字段中269个已读，最后敌方被击倒后能量UI隐藏，当前值留空、最后可见8单列。这是用户确认的样例复核结果，不是自动识别准确率统计。动作时间是近似锚点，部分单次动作的状态只能保留回合参照，字段中有明确说明。

## 回合和伤害规则

双方各6只精灵，每回合每方一次常规行动：使用技能、聚能或切换。聚能规则恢复5能量，实际净变化以 HUD 为准；例如6→10实际增加4。首领化每方一次，不占常规行动，动画占据场地，不据此额外开回合。

强制切换属于当前回合：尚未行动就被击倒时，强制切换占用未执行的行动；已经行动后被击倒时，保留已发生行动并追加本回合强制切换，不扣下一回合的行动。双方同回合都可能受伤，伤害归属到事件发生时的出战目标。

没有连击效果的技能取同一伤害实例的最后一个读数，不累加数字动画。不同属性字体颜色不同，白色表示普通系，不能仅据白色判定伤害来源。技能伤害与冻结等状态效果分列；本片化蝶被冻结按百分比生命斩杀，比例未知，不推算为固定伤害公式。防御技能的“应对”提示不代表又进行了一次常规行动，也不能用提示出现时间直接判出手顺序。

阿布和布灵布灵是不同精灵；阿布暂未入库，可保留原名和空 ID。月牙雪熊的显示名“樊振东宝”与原名分开，皮肤头像待同步；不能因原生头像匹配不足而把用户确认的身份改成别的精灵。

## 尚未实现

Windows MSS 实时捕获、自动区域定位、完整自动分帧/回合归属、头像连续3～5帧确认，以及自包含 Windows exe 打包尚未实现。20 FPS 只是早期离线采样后的暂定捕获频率，不是目标 Windows 的性能承诺；应以原生窗口捕获的实际延迟、短浮字覆盖和 CPU 占用继续验证。
