# 前端设计：战斗伤害范围计算器

> 状态：设计稿（2026-11-21）。第 2 步范围计算核心、第 3 步最小网页、第 4 步完整页面（左右两栏、增减益、战斗记录、生命百分比、本地保存）已完成；6 对 6 的后端核心也已完成（`roco_team.py`）。第 1～7 节描述的是旧单只精灵页面，6 对 6 改版计划见第 8 节。
>
> 目标：在浏览器里估算对局伤害。我方精灵的性格、天分在战斗前就知道；对方只知道是哪个精灵，性格和天分未知，所以所有伤害先显示为一个范围，再通过战斗中记录的真实伤害逐步缩小。

## 1. 第一版做什么

第一版只做一条主流程：

1. 选择我方精灵、性格、天分（全部已知）。
2. 选择对方精灵（只知道种类，性格和天分未知）。
3. 选择我方技能，查看伤害范围、占对方生命的比例、能否击倒。
4. 填写双方当前的增减益、天气、星陨层数。
5. 在战斗记录里填“我方某只精灵用某技能打了对方多少血”，程序自动缩小对方的属性范围，并给出可能的性格。
6. 记录“这一轮后对方还剩百分之多少生命”，进一步缩小对方的生命范围，并排除一部分性格。

第一版暂不做：

- 对方打我方技能的伤害范围（后端已完成，待页面接入）。
- 多只对方精灵同时追踪（后端已完成 6 个位置，待页面接入）。
- 速度先后、先手、换人。
- 特性、道具、场地、其他印记。
- 可学技能过滤（学习表数据已生成，待页面接入）。

## 2. 技术方案

不安装任何新软件：

- 后端：Python 自带的 HTTP 服务（`http.server`），复用现有 `roco_calc.py`。
- 前端：普通 HTML/CSS/JavaScript，无 Node、无打包工具、无外部 CDN，断网也能用。
- 运行：`python server.py`，浏览器打开 `http://127.0.0.1:8000`。
- 服务只监听本机（127.0.0.1），局域网外无法访问。

计划新增的文件：

│ 魔防/速度，各一排加减按钮   │ 魔防/速度，各一排加减按钮      │

├──────────────────────────────────────────────────────────┤

交互要点：

- 对方的数值用“最低～最高”显示；只剩下一个值时显示单个数。
- 鼠标悬停或展开，可以看到“可能的数值列表”和“可能性格列表”。
- 每条战斗记录可以编辑、删除；改动后所有范围立即重算。
- 页面状态自动保存在浏览器本地（localStorage），刷新不丢；以后再加导出/导入 JSON。

## 4. 对方未知信息怎么算成范围

### 4.1 未知的是什么

- 对方是哪个精灵、什么属性：看得到，已知。
- 对方性格：30 种，每种提升一项属性、降低另一项属性，没有“不加不减”的性格。
- 对方天分：每项只能是 **0、7、8、9、10**（用户确认，不存在 1～6），至少一项有加成、至多三项有加成（用户确认）。

这两条约束作用在“整只精灵”上，不是六项属性各算各的：一只精灵恰好有一个提升项和一个降低项；全精灵的天分加成最少一条、最多三条（不会是六项全 0）。所以确定了某一项的提升或加成，就会连带排除其他项的同类可能。下面的候选集合一律按整只精灵维护。

### 4.2 整只精灵的候选集合

不再把六项属性分开算，而是给整只精灵保留一份候选集合：

```text
天分配置：6 项各取 0 / 7 / 8 / 9 / 10，至少 1 项非 0、至多 3 项非 0
  = 6×4 + 15×4² + 20×4³
  = 24 + 240 + 1280
  = 1,544 种
  （“全 0”那种要排除）

整体候选：30 种性格 × 1,544 种天分配置
  = 46,320 种
```

每个候选就是一只“完整可能的对方精灵”（一种性格 + 六项天分）。过滤记录时在这个集合上整体求交，性格和天分之间的相互限制自动生效：性格的提升项只有一个，别人就不能再提升；天分已经有三项非 0，第四项就只能为 0。

单独看一项属性时，46,320 个候选里最多只有 **15 个不同数值**（5 档天分 × 性格对该项的“提升 / 降低 / 不影响”3 种）。某一项天分为 0 的取值仍然可能出现，因为“至少一项有加成”可以由其他项满足。所以界面上每项显示“最低～最高”和“15 个可能取值”，但过滤是在整体集合上做的。

以 60 级的龙息帕尔为例，初始范围是：

| 属性 | 最低～最高 | 不同数值个数 |
|------|------------|--------------|
| 生命 | 362～510 | 15 |
| 物攻 | 185～270 | 15 |
| 物防 | 189～274 | 15 |
| 魔攻 | 116～177 | 15 |
| 魔防 | 145～217 | 15 |
| 速度 | 158～234 | 15 |

这些数字全部由现有的 `calculate_stat()` 逐个组合算出，不另写公式。

### 4.3 从属性范围到伤害范围

伤害公式里，防御在分母，所以：

- 防御越高，伤害越低；防御越低，伤害越高。
- 攻击越高，伤害越高。

因此只需要取候选值的最小值和最大值，就能得到伤害范围：

```text
最大伤害 = 用最低防御算出的伤害
最小伤害 = 用最高防御算出的伤害
```

例：水灵（聪明、魔攻天分 10，魔攻 270）用气泡打未知的龙息帕尔：

```text
魔防候选 145～217
防御 145 → 伤害 210
防御 217 → 伤害 140
所以伤害范围是 140～210
```

### 4.4 战斗记录怎么缩小范围

一条记录包含：哪一方攻击、用的什么技能、打了多少血、打了几下、当时的天气 / 增减益 / 星陨层数。

处理方式：

1. 从整体候选里，按受击方对应防御属性的不同取值分组（物攻技能看物防，魔攻技能看魔防，最多 15 个取值）。
2. 对每个候选值，用与网页相同的伤害公式模拟一次。
3. 只保留模拟结果正好等于记录伤害的候选值。
4. 剩下的候选值决定新的范围、剩余组合数和可能性格。

例：记录“雨天，水灵用气泡打了龙息帕尔 341”：

```text
魔防的 15 个不同取值里，只有 156 能打出 341
→ 魔防天分必为 0
→ 性格既不提升也不降低魔防，只剩 20 种性格
→ 其余五项天分至少一项、至多三项非 0，共 820 种天分配置
→ 整体候选剩 20 × 820 = 16,400 种
```

也就是说，这一条记录已经确认了对方的魔防天分为 0，并排除了 10 种会改变魔防的性格。

如果一条记录没有任何候选值能对上：

- 不缩小范围，保留记录并标红提示。
- 提示内容：“这条记录和当前规则对不上，请检查伤害、天气、增减益或星陨层数。”
- 常见原因：对方有减伤特性/道具、记录的是多段技能的单段伤害、天气或增减益填错。

### 4.5 多条记录

- 所有记录都在同一个整体候选集合（46,320 种）上过滤，每处理一条就把集合再缩小一次。
- 不同属性的记录不是“分别过滤、最后简单合并”，而是同一次过滤；性格“只有一个提升项”和“天分最多三项”的约束会随着每条记录自动生效。
- 第一版按填写顺序处理；某条记录把候选集合过滤到 0 时，标红并跳过这一条，不让整个结果变空。

例（继续上面的龙息帕尔）：

```text
初始                                    46,320 种 · 30 种性格
记录 ①：雨天气泡 341 → 魔防 156          16,400 种 · 20 种性格
         （魔防天分 0，性格不碰魔防）
记录 ②：195 伤害后显示 50% → 生命 391      4,416 种 · 12 种性格
         （生命天分 0，性格也不碰生命）
```

第二条记录不只是把生命锁定。因为性格的提升项和降低项只能在除魔防、生命之外的另外四项里选，所以“可能性格”从 20 种直接缩到 12 种；六项天分里已经固定两项为 0，剩下四项至少一项、至多三项非 0，天分配置只剩 368 种。如果按单项分开算，这两条信息不会互相影响，范围会偏大。

界面展示的是：每项属性的最低/最高值和 15 个可能取值，加上整体“还剩多少种候选 / 多少种性格”。

### 4.6 生命百分比记录

对方不会显示具体生命，只显示“剩余生命 ÷ 最大生命”的整数百分比，默认四舍五入。记录一条生命百分比需要两个数：

- 当时显示的百分比，例如 `50`。
- 到那一刻为止，对方累计受到多少伤害。默认由之前记在同一只对方精灵身上的伤害自动累加，也可以手动修改（中途开始记录、对方回血、漏记伤害时用）。

处理方式和伤害记录一样，逐个试剩下候选的生命值（最多 15 个不同数值）：

```text
显示百分比 = round((最大生命 − 累计伤害) ÷ 最大生命 × 100)
只保留算出来等于记录值的候选
```

例：无雨时水灵气泡打龙息帕尔是 195 伤害，打完后对方显示还剩 **50%**：

```text
391 → (391−195)/391 = 50.13% → 显示 50
394 → (394−195)/394 = 50.51% → 显示 51
其他生命候选也都不是 50
→ 最大生命锁定 391
→ 生命天分是 0，性格不改变生命
→ 可能性格从 30 种缩小到 20 种
→ 整体候选从 46,320 种缩小到 16,400 种
```

如果同时还记录了别的属性（例如魔防锁定 156），两条记录在同一个整体集合上过滤，“可能性格”会一起缩到 12 种，因为性格的提升/降低项只能从没被排除的另外四项里选。

边界情况：

- **百分比取整方向**：先按四舍五入。接口里留一个 `round` / `floor` / `ceil` 选项；如果记录怎么都对不上，可以换一种取整方式再试。
- **0%**：表示剩余生命不足 1%，可能已经倒下。只用来给最大生命一个上界，不强行推断具体数值。
- **治疗**：回血后“累计伤害”不再等于已损失生命，需要手动改小这个数字。
- **护盾**：护盾吸收的伤害不算生命损失，百分比可能对不上；这时会提示而不会硬算。
- **过量伤害**：累计伤害可以大于最大生命，这种情况只保留“已经击倒”的判断。

### 4.7 生命占比和能否击倒

对方生命也是未知的。生命的最低/最高值同样取自“当前剩下的整体候选”，不是固定初始范围。第一版用“最乐观 / 最悲观”两组数字给出一个略宽的范围：

```text
最小占比 = 最小伤害 / 最大生命
最大占比 = 最大伤害 / 最小生命

一定击倒：最小伤害 ≥ 最大生命
不能击倒：最大伤害 < 最小生命
其余情况：可能击倒
```

例：气泡伤害锁定 341、对方生命范围 362～510 时，341 < 362，所以“不能击倒”。

### 4.8 已知的近似

- 每项属性展示的仍是“剩余候选里的最低/最高值”，不是逐值精确区间；生命占比和能否击倒用的是这两组边界值，比真实可能性略宽。
- 第一版的伤害记录只依赖一个防守属性（物防或魔防），所以用整体候选取最低/最高防御就足够。以后做“对方打我方的伤害”时，一次伤害同时依赖攻击和防御两项属性，需要按成对取值处理，不能只用单项范围。
- 对方可能有减伤特性、道具、护盾，这些目前都不知道；记录对不上时会提示，而不是强行套公式。
- 生命百分比依赖“累计伤害”记录完整。治疗、护盾、漏记伤害不会自动识别，需要手动调整累计伤害。
- 生命百分比默认按四舍五入处理；如果游戏实际是向下或向上取整，需要切换选项。

## 5. 接口设计

### 5.1 Python 函数层

新增 `roco_analysis.py`，核心函数：

```python
def analyze_battle(state: dict) -> dict:
    """输入整场状态，返回对方属性范围和当前技能伤害范围。"""

def build_candidates(pet, level=60) -> list:
    """返回 46,320 个整体候选：{nature, talents}。"""

def apply_observation(candidates, observation, ...) -> list:
    """用一条战斗记录在整体候选上过滤。"""
```

实现方式（保证速度）：

- 46,320 个候选固定编号 0～46,319。
- 每项属性的每个取值（最多 15 个）预先算好“拥有该取值的候选编号位图”，用一个 Python 大整数表示。
- 一条记录先用当前状态算出允许的取值，再把这些取值的位图“或”起来，和当前位图求“与”。
- 一次过滤就是几次大整数位运算，耗时基本不随候选数增长；全部位图加起来只有几百 KB。
- 过滤完，最低/最高属性值、可能性格、各天分是否已满三项，都从剩余位图里按 15 个取值、30 种性格各查一次得出。

网页服务只是这些函数的薄包装，以后其他程序也可以直接 `import roco_analysis` 调用。

- `builds.remaining` 是剩下的整体候选数（性格 + 六项天分），`builds.total` 固定 46,320；`natures_remaining` 是剩余性格数。
- `observations[].kept` 是这条记录处理完之后的剩余整体候选数。
- `knockout` 取值：`certain`（一定击倒）、`possible`（可能击倒）、`impossible`（不能击倒）。
- 出错时返回 HTTP 400 和 `{"error": "中文原因"}`，不返回堆栈。

**生命百分比记录示例**

另一场：无雨时水灵气泡造成 195 伤害，打完后对方显示还剩 50%。在 `observations` 里加一条：

```json
{
  "type": "hp_percent",
  "hp_percent": 50,
  "total_damage": 195
}
```

对应响应里的生命会变成：

```json
"hp": {"min": 391, "max": 391, "possible_values": [391]},
"builds": {"remaining": 16400, "total": 46320},
"natures_remaining": 20,
"observations": [
  {"index": 0, "type": "hp_percent", "matched": true, "kept": 16400, "message": null}
]
```

说明：

- `total_damage` 是“到那一刻为止，对方累计受到的伤害”。前端默认用之前的伤害记录自动累加，用户可以手动修改。
- `type` 省略时默认按 `damage` 处理，方便只记伤害的旧请求继续使用。
- `hp_percent_rounding` 支持 `round`（四舍五入，默认）、`floor`（向下）、`ceil`（向上）。
- 生命百分比和伤害记录可以混在同一个数组里，按填写顺序逐条应用。

### 5.3 增减益接口

请求里每方一个 `buffs` 对象：

```json
{"atk": 0, "def": 0, "spa": 2, "spd": 0, "spe": 0}
```

- 物攻/物防/魔攻/魔防每层 10 个百分点；速度每层 +10 点。
- 范围 −99～99 层，和命令行一致。
- 每条战斗记录单独保存当时的增减益，不用现在的状态解释以前的伤害。
- 页面“高级”区保留手填 `damage_reduction_percent`、`damage_multiplier_percent`、`hits` 的入口，对应命令行已有的参数。

## 7. 决策记录

- 前端不引入 Node、不安装新软件，用 Python 自带服务器 + 普通网页。
- 对方信息按“整只精灵”联合推断：30 种性格 × 1,544 种天分配置 = 46,320 个候选；“恰好一个提升项和一个降低项”“天分至少一项、至多三项非 0”在过滤时自动生效（2026-11-21 用户确认）。
- 天分只允许 0、7、8、9、10（2026-11-21 用户确认）。
- 候选集合用“编号 + 位图”实现：每条记录是一次位图求交，避免每次从头重算 46,320 个候选。
- 伤害范围只取防御候选的最低/最高值，因为伤害随防御单调变化。
- 战斗记录采用“候选值逐个模拟、保留能对上的”方式，不用反推公式。
- 记录对不上时不缩小范围，只警告，不静默改数。
- 服务状态放在前端；后端接口无状态，每次请求带完整状态，方便以后接别的程序。
- 第一版只做“我方打对方”；对方打我方在接口里预留 `attacker` / `defender` 字段。
- 对方生命只显示整数百分比，默认四舍五入（2026-11-21 用户确认）；接口保留 `round` / `floor` / `ceil` 切换。
- 生命百分比记录使用“当时累计伤害”而不是“这一下打了多少”，由前端自动累加、允许手动修改；治疗和护盾需要手动调整。

### 页面结构

```text
天气 [雨天 ▾]                         战斗记录
┌───────────────────────┬───────────────────────┐  ┌──────────────────────┐
│ 我方 6 个位置          │ 对方 6 个位置          │  │ ① 我方 水灵 用 气泡   │
│ 当前出战：位置 1 水灵  │ 当前出战：位置 1 帕尔  │  │    打对方 帕尔 195    │
│ 生命 306 / 383         │ 生命 312（显示 80%）   │  │    打完剩 50%         │
│ 技能 1 气泡 195（50%） │ 对方技能 1 龙之利爪    │  │    天气、双方增减益    │
│ 技能 2 水炮 ...        │    160（我方剩 146）   │  │ ② 帕尔生命变成 80%    │
│ ...                    │ ...                    │  │    实际回血 +116       │
└───────────────────────┴───────────────────────┘  │ [＋伤害] [＋生命变化] │
                                                    └──────────────────────┘
```

### 交互要点

- 双方各 6 个位置；点某个位置切换“当前出战”，技能伤害表只比较当前出战的一对。
- 我方每个位置手动选最多 4 个技能；对方技能初始为空，可手动添加，数量不限。
- 技能下拉按 `data/learnsets.csv` 过滤，只显示该精灵能学的技能；对方记录里出现的技能自动加入对方技能列表。
- 每个我方技能旁边显示：伤害范围、对方剩余生命百分比范围、能否击倒。
- 每个对方技能旁边显示：伤害范围、我方剩余具体生命范围、能否击倒；我方不显示百分比。
- 战斗记录单独一栏，每条可以独立删除；修改记录后重新请求后端。
- 记录类型：
  - 伤害：哪一方、哪个位置、什么技能、伤害、打完后的剩余（对方填百分比，我方填具体生命）。
  - 生命变化：对方填百分比，可选填实际变化量（正数回血、负数掉血）；我方直接填具体生命。
- 页面状态存到浏览器本地，建议使用新的存储键，避免把旧的单只精灵状态误读成 6 对 6 状态。
